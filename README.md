# AI-sync-menu (pos-sync)

Інструмент для зіставлення меню з POS-системи (Syrve / Poster) з меню в Choice QR. Вирішує задачу, де назви позицій у двох системах не збігаються: "Піца Маргаріта" vs "Піца Маргарита 30см".

## Яку проблему вирішує

При підключенні ресторану до Choice QR потрібно вручну зіставити сотні позицій між POS і Choice. Назви часто відрізняються через транслітерацію, скорочення або формат. Без автоматизації — кілька годин рутини.

## Архітектура: каскадний матчинг

Ендпоінт `/api/match` проходить два кроки послідовно.

### Крок 1 — Dice coefficient (детермінований, без API)

Кожна позиція Choice порівнюється з усіма позиціями POS через [Dice coefficient](https://en.wikipedia.org/wiki/S%C3%B8rensen%E2%80%93Dice_coefficient) (bigram-схожість рядків). Реалізація в `pos-sync/src/dice.js`.

| Результат | Умова | Що відбувається |
|---|---|---|
| `high` | score > 0.4 + ціна ±50 грн | → **matched**, застосовується автоматично |
| `medium` | score ≤ 0.4 або ціна не збігається | → **review**, чекає підтвердження людини |
| нічого | позиція не знайдена | → **unmatched** |

### Крок 2 — Claude Haiku (semantic fallback)

AI запускається тільки для `medium` і `unmatched` позицій. `High`-результати Dice AI не торкає.

Для кожної позиції модель отримує топ-5 кандидатів за Dice і вибирає найкращий або повертає `null`.

**Механізми надійності** (`pos-sync/src/ai-match.js`):

| Механізм | Що робить |
|---|---|
| Валідація JSON | Raw-відповідь парситься regex'ом, потім `JSON.parse`. Якщо невалідно — retry |
| Membership-валідація posId | Якщо модель повернула posId якого немає у списку кандидатів — відповідь відхиляється. Захист від hallucination: некоректний ID не потрапить у POS |
| Retry (до 2 спроб) | При невалідній відповіді — повторний запит із нагадуванням про формат |
| Fallback | Якщо всі спроби невдалі — позиція залишається в `unmatched`, дані не псуються |

Всі AI-результати позначаються `aiSuggested: true` і **завжди** потрапляють у review — ніколи не застосовуються автоматично.

Якщо `ANTHROPIC_API_KEY` не задано — сервіс запускається в Dice-only режимі без помилок.

## Стек

- Node.js + Express
- Anthropic API (Claude Haiku)
- Dice coefficient (власна реалізація, без зовнішніх залежностей)
- Choice QR Open API (OAuth2, проксується через Express)

## Запуск

```bash
cd pos-sync
npm install
cp .env.example .env   # ANTHROPIC_API_KEY, CHOICE_CLIENT_ID, CHOICE_CLIENT_SECRET
npm start
# → http://localhost:3000
```

Dice-only режим — просто не вказуй `ANTHROPIC_API_KEY`.
